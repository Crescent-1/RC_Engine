The problem no prompt can solve

why this needed engineering, not prompting

After a few hundred generated passages, students detect structural repetition — argumentative rhythm, reversal timing, question logic — long before any embedding-similarity check fires. Fixed prompts guarantee this failure: every output is the same essay wearing a different topic.

  • Structure as a sampled variable, not a prompt constant. A deterministic composer samples blueprints from combinatorial component libraries (32 argument families; 20 each of personas, endings, rhythms, revelation patterns, distractor profiles, question topologies) under exclusion windows, usage-decay weighting, and named compatibility rules.
  • Cost-tiered multi-model orchestration. Claude Opus renders passages, Sonnet refines blueprints and adversarially blind-solves the questions, Haiku audits structural compliance and judges against blueprint-derived rubrics. A pre-call cost ledger makes overspend impossible by construction.
  • A 9-channel novelty auditor. Levenshtein over paragraph-function strings, DTW on authorial commitment curves, Burrows' Delta stylometry, Jensen–Shannon divergence on distractor mechanisms, χ² answer-pattern tests, embedding cosine — semantics is deliberately just one channel of nine.
  • Evaluation gates before spend. Cheap local checks run before expensive API calls; failed structure triggers targeted regeneration directives, not full re-runs. Full audit trail in SQLite: blueprints, fingerprints, novelty scores, per-call spend, corpus-health drift monitoring.
